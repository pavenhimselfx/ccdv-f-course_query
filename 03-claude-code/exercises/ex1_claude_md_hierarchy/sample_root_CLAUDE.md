# Example root-level CLAUDE.md (for reference — read before writing your own)

This is an illustrative example of what a **project-root** `CLAUDE.md` might look like,
for a fictional project. It's here so you can see the *shape and tone* of realistic
project-wide conventions before you write your own for `fake_repo/CLAUDE.md`. Don't copy
it verbatim into your exercise — write one that fits the fake repo you're building.

# Project conventions

This is a Python/TypeScript monorepo: a FastAPI backend and a React frontend, deployed
as two separate services.

## Stack

- Backend: Python 3.12, FastAPI, SQLAlchemy, PostgreSQL.
- Frontend: TypeScript, React, Vite.
- Package management: `uv` for Python, `pnpm` for JavaScript.

## Before you're done with any change

- Run `make test` from the repo root — it runs both the Python and JS test suites.
- Run `make lint` — this runs `ruff` and `eslint`. Fix everything it flags; don't
  suppress warnings without a comment explaining why.
- Never commit directly to `main`. Work on a feature branch and leave the PR for a human
  to open unless explicitly asked to open one yourself.

## Code style

- Python: follow PEP 8, use type hints on all new functions, prefer f-strings.
- TypeScript: functional components only, no class components in new code.
- Keep functions short and single-purpose; prefer several small functions over one large
  one.

## Do not touch

- `**/migrations/` — database migrations are generated by Alembic and hand-edited only
  in exceptional cases; ask before touching one.
- `.env*` files — never read, print, or modify environment files; they may contain
  secrets.
- `vendor/` and `node_modules/` — third-party code, never edited directly.

## Commit messages

Use conventional commits (`feat:`, `fix:`, `chore:`, `docs:`, ...) with a short
imperative summary line.
